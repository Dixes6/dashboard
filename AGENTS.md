# Manicure Dashboard — правила для ИИ-агента

## О проекте
Dashboard для мастера маникюра (один владелец): календарь записей, учёт доходов и расходов, клиенты, прайс.
Универсальный: ничего не захардкожено под конкретного человека. Название, услуги, график, цены — в БД и настройках.
Клиентского сайта пока нет, но модель данных должна позволить добавить его позже (источник записи, длительность услуг, статусы).

## Стек
- Backend: Python 3.12+, FastAPI, SQLAlchemy 2.x, Alembic, PostgreSQL, pydantic v2, pytest
- Frontend: React + TypeScript + Vite + Tailwind, PWA, mobile-first (Android, экраны 360–412px)
- Инфраструктура: Docker Compose, Caddy

## Структура
- backend/app/ — api/, models/, schemas/, services/, core/
- backend/alembic/, backend/tests/
- frontend/src/ — pages/, components/, api/, lib/
- docs/ — DESIGN.md и прочая документация

## Правила работы
1. Делай только то, о чём просят. Без рефакторинга и фич «заодно».
2. Маленькими шагами. После каждого шага: какие файлы изменены, как запустить и проверить.
3. Схему БД меняй только через миграции Alembic и только после моего подтверждения.
4. Бизнес-логика (доходы, слоты, статусы) живёт в backend/app/services/, не в роутах и не во фронтенде. Покрывай тестами.
5. Деньги — целые числа в рублях (int), никаких float.
6. Время храни в UTC (timestamptz), показывай в часовом поясе из настроек.
7. Цена услуги копируется в запись на момент визита. Смена прайса не меняет прошлые записи.
8. В доход идут только записи со статусом «Состоялась». Итоговую цену можно править вручную, цена по прайсу хранится отдельно.
9. Записи и клиентов удаляй мягко (deleted_at), не физически.
10. Интерфейс на русском, mobile-first, зоны нажатия не меньше 44px.
11. Дизайн строго по docs/DESIGN.md: только токены оттуда, никаких произвольных цветов.
12. Секреты только в .env (не коммитить), .env.example обязателен.
13. Библиотеки и шрифты ставь локально через npm/pip, без внешних CDN.
14. Перед сдачей задачи линтер и тесты должны проходить.
15. Что-то неясно — спроси, не придумывай.
